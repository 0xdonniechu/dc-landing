IT PLANS FIRST, THEN CHECKS ITS OWN WORK

Ask an agent for a job on its own and you end up being the checker: you read it, spot what is off and prompt again. The kit writes a plan first, builds against it, then scores itself and only hands you work that passes.

  • A plan before the build. Every task has a goal, a scope and a check, written down before any code.

  • Two gates: scope and quality. It finds what drifted outside the task and what is weak, and fixes both first.

  • A reviewer that is not the builder. A second agent reads the diff cold and returns pass or fail with reasons.
