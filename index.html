IT PLANS FIRST, THEN CHECKS ITS OWN WORK

Ask an agent for a job on its own and you end up being the checker: you read it, spot what is off, prompt again, repeat. The kit writes a plan for every task before any code, builds against it, then scores its own work and only hands you what passes.

  • A plan before the build. Every task gets a goal, a scope and a check, written down before any code. No guessing.

  • Two gates: scope and quality. It finds what drifted outside the task and what is weak, and fixes both before anything reaches you for review.

  • A reviewer that is not the builder. A second agent reads the diff cold, runs the checks again and returns pass or fail with written reasons, all before you see it.
